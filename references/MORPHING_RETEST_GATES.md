# Morphing Abstract_text1 retest: build and evidence gates

Scope: user-supplied `EXECUTION_LOG.md`, `SKILL_ITERATION_ISSUES.md`, and referenced probe JSON from the successful `Morphing Abstract_text1` run. Environment: Substance Designer 16.0.3, sd_mcp_plugin 3.3.0. The final run passed 20/20 unit cases and three image comparisons (MAD about 0.00012; max 1/255), but its first build exposed silent-zero failures and its Sequence layout was mirrored. These documents are evidence, not instructions or authorization to edit that project. All runtime-specific observations below require a matching-version/current-context probe before reuse elsewhere.

## P0: prevent silent-black output before cook

1. **Marked PP root dimension (observed 16.0.3).** A PP inner graph's float1 and float4 roots marked and cooked; tested float2/float3 roots (`vector2/3`, `const_float2/3`) returned zero `getOutputNodes()` without an API error and cooked black. A normal `SDSBSFunctionGraph` marked float1/2/3/4 roots in the separate function probe. Therefore, for this verified PP context, lower intermediate float2/3 diagnostics through a float4 carrier (known spare components) or a scalar channel, then read back the marked count and pixel value. The mark call returning normally is not evidence. For unknown versions, probe the dimensions rather than claiming an all-version engine rule. `check_marked_root` in `scripts/project_validation.py` fails closed by version.
2. **Value-spine reachability.** After wiring, reverse-traverse actual explicit source→consumer connections from the marked output. Every planned live `Set`, pre-loop Sequence, and While/control result required by the IR must appear in that closure. An intentionally dropped dead store is excluded explicitly, not silently accepted. A `Get('name')` does not itself form an edge to a same-name Set. In the failed Morphing build, pre-loop Sets and the outer While were absent from the output closure, so the image was black; connecting the pre-loop Sequence to the While `init` and consuming the outer While output made the path live. Never feed an external Sequence into a While Body. `check_output_reachability` is a static aid, not a cook substitute.
3. **Shallow diagnostic path.** If an image is black, test one independent channel per cook: known constant (pipeline), pre-loop state, loop counter, accumulator, then final loop state/output. Encode signed or large values before the PP root. Read exact files and dimensions. Do not diagnose all five through one deep nested mux or infer “math wrong” before reachability is checked.
4. **Band ownership before placement.** Every node in a planned Statement graph needs a resolved statement band or explicit shared/bridge role. Inline constants inherit from their consumer when the consumer band is unique. Multiple consumer bands are an ambiguous shared node requiring an explicit IR decision; unconsumed/cyclic nodes are unresolved, never silently assigned band 0. Place different expression depths in different X columns; same-depth siblings need Y separation. Band height derives from the busiest depth, not total node count. `infer_bands` and `band_height_from_levels` in `scripts/layout_intelligence.py` provide deterministic checks.

## P1: avoid builder and evidence contamination

- `execute_sd_code` may provide a fresh top-level namespace while Designer's Python process and `sys.modules` persist. A modified helper imported in an earlier call may remain cached. Before a staged rerun, refresh **only this run's owned module names** (for example `sys.modules.pop('morphing_graphs', None)`), then import again; do not clear unrelated modules or assume `importlib.reload` happened automatically.
- Avoid `exec`-ing multiple helper files into one shared namespace when they define generic names such as `sw`/`c1`. Import libraries as separate modules; execute only the driver in its intended namespace, and use qualified helper names.
- Export artifact selection must use the **actual graph identifier read back after creation** or a recorded full filename. The later Sun shower run established that `exportSDGraphOutputs` named its BMP `<actual_graph_identifier>_output_0.bmp`; a requested identifier can be auto-suffixed. `coords` matched `coords2` in the earlier failed probe. A unique run-owned export directory is preferable; when reusing one, remove only exact outputs owned by this run after verifying their paths. Do not delete other files by broad glob or substring. `exact_graph_export_match` rejects missing and ambiguous matches.
- In the observed atomic-definition preflight, `sbs::function::length` and `lt` did not exist. `length(v)` can be represented as `sqrt(dot(v,v))` for the tested float3 case; the built-in Functions library separately contains `length_vec2/3`. `x < y` may use the verified `gt(a=y,b=x)` mapping. Always check the current atomic definitions **and** relevant built-in library Functions before claiming a function is unavailable. `dot` is a scalar dimension-fixing node; `length` is not an atomic node to instantiate in this environment.
- `$outputsize` is a log2 exponent pair for power-of-two dimensions: `(5,5)` produced 32², whereas passing pixel dimensions produced an unintended 8192² export in this run. Set/read inheritance mode before the value; both comp and PP were `Absolute` in the successful probe. This is a verified recipe for that probe, **not** the only valid inheritance combination. Always verify the exported BMP dimensions; for other modes use their actual resolved behavior. `output_log2_pair` validates the intended exponent pair offline.

## P2: scoped semantics and reproducible diagnostics

- **Parameters:** in one 16.0.3 PP session, `Get('iTime')` read a parent comp parameter (0.251 for 0.25) and `Get('gOnly')` read a graph-only parameter (0.749 for 0.75). An unconnected `#iTime` PP port read 0. `getInputIdentifiers()` returned `[]` despite readable parameters, so it is not a sufficient existence check. Prefer an explicitly declared, calibrated parent parameter for Shadertoy time; a `#Name` port must have an actual source connection. These observations do not establish every name-shadowing priority or `$time` behavior in other contexts.
- **Coordinates/size:** with 32² output and both inheritance modes Absolute, measured `$pos` sampled at pixel centers with Y increasing downward; `$size≈(32,32)` and `$sizelog2≈(5,5)` within 8-bit encoding error. Another 16.0.3 project reported unit-like `$size`; the cause of that discrepancy was **not isolated**, so do not claim inheritance mode caused it. Probe the current PP with a float4 root: encode `$pos.x`, `$pos.y`, `$size.x/256`, `$size.y/256`; if alpha is not exported, use a second RGB probe for the fourth channel. Confirm actual output dimensions and BMP row order. Map bottom-origin shader coordinates only after an asymmetric oracle comparison.
- **Nested While / Get:** the retest's inner Body updated an accumulator across two outer iterations and returned about 22 after encoding (expected 22). Same-scope fresh Gets read 0.698/0.8 for written 0.7/0.8. This demonstrates feasibility in that graph; it does not repeal the conservative Sequence-first handoff or prove bare Get works in every scope. Preserve both observations in the report.
- **GLSL matrices:** `matN` constructor vectors are columns. For `M*v`, derive rows by transposing those columns, then dot each row with `v`; for `v*M`, dot `v` with each original column. In the retest, the `mat3` ACES path went from 17/20 to 20/20 unit passes after that correction. Test every distinct matrix with a non-symmetric, nonzero input (including signs), rather than relying on an image that can look approximately correct. `glsl_matrix_rows` is a pure helper for N=2/3/4.
- **Probe range:** a PP float4 diagnostic channel carrying raw 22 saturated at code 255 and could not distinguish large values. Encode with a stated scale (22/64 was readable), keep expected channels strictly inside (0,1), and reject saturation/non-finite values as numeric evidence. `check_probe_encoding` is an offline guard.
- **Resource identity/reentrancy:** Designer auto-suffixed a colliding Function identifier with `_1`. At stage start, enumerate exact owned resource IDs and record the actual identifier after creation. If one already exists, either reuse it only after identity/fingerprint checks or stop for a scoped rebuild decision; do **not** automatically purge a resource just because its name has a familiar prefix. Only run-owned scratch resources may be cleaned, with ownership and unsaved-state safeguards.

## Acceptance separation

Record structure, per-function numeric, PP image, layout, and session residue separately. This retest's numeric/render result is PASS; the reported Sequence-left layout is FAIL. Static helpers prevent known failure shapes but do not certify native Designer behavior. The 16.0.3 evidence does not certify 16.0.5 or unknown versions.
