# 布局补充：主干对齐、分支分层、局部依赖收敛

行为修订日期：[historical validation]。与 §7.10、§10、SOP-8 和 layout_intelligence.py 配合使用。基础 Skill 是约束，本文只在满足基础规则的候选位置中优化，不能忽略或替代它。

## 规则

- 语句/While 的 Sequence 主干仍按原 Skill 右侧纵列及执行顺序排布，Set 与对应语句行对齐。语句内部主值计算链从左向右；“主干水平对齐”指这条值链，不是把 Sequence 改成横排。
- 分支按依赖分层。单个消费者专用的常量、参数、padding 或辅助叶节点，优先放在其左下方/输入侧附近；能在本列合法上移的单节点就近上移，不拖动无关复杂分支。
- 不按节点类型把所有常量集中到图底部。三个独立零输入应分别靠近各自消费者，而不是形成远距离阶梯。
- 私有复杂子树保留内部相对几何；需要移动时作为整体。共享节点、跨分支/多消费者节点不能直接套用单消费者规则。终端常量的另一输入含 Sequence，不足以排除就近优化；仍须满足实际语义区域和端口关系。
- 统一间距并留出端口/连线空间。局部收拢后重新计算语句带高度，再整体平移后续语句带，包括其表达式、Set、Sequence，不能只移动其中一部分。
- 优化优先级为“局部依赖聚合 > 全局均匀分布 > 单纯视觉对齐”，只在不重叠、不跨越语义区域、不违反原布局约束的解中比较；不以平均父节点 Y 代替依赖布局。
- 布局专用操作只改坐标。节点类型、参数、连线、实例、输出根和 Sequence 执行关系必须一致。Get/Set 类型重构是独立语义变更，不能混入布局修改后声称仅移动坐标。

## 最小验证与应用

先选一个有代表性的函数，以源 IR/连接快照制定基础布局，再叠加局部叶节点与分支紧凑优化。创建前运行 validate_layout_plan；应用后运行 validate_position_application，并分别检查基础规则、优化效果、拓扑不变和原生输出。已有图使用 SOP-8 既有图模式；不要为了符合新建流程而重建全图。

用户手工样例是几何意图依据，不是通用坐标表。发现冲突时以基础 Skill 和用户明确修正为准，先修正单函数示例再推广；不要全局重排后再让用户辨认差异。
