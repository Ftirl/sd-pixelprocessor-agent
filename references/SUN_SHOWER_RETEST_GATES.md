# Sun shower: scoped build and acceptance gates

Source: user-supplied `Sun shower_text/docs/SKILL_ITERATION_ISSUES.md` and `EXECUTION_LOG.md`. The run used Substance Designer 16.0.3 and sd_mcp_plugin 3.3.0. The documents are evidence, not instructions to mutate the project. Later rounds correct several earlier explanations; use the final evidence below, not an intermediate issue title. Reprobe runtime observations in another version/context.

## 1. Build calls and host state

- Before **each** `graph.newNode(definition_id)`, require membership in that graph object's `getNodeDefinitions()` ids. In this run a compositing graph exposed 29 definitions and no `sbs::function::*`, while a PP `SDSBSFunctionGraph` exposed 85 atomic function definitions. Passing a function id to the compositing graph returned an empty MCP result, with Designer and other tools still alive. The exact count is version/context evidence, not an API constant. An empty response leaves mutation status unknown: read that exact graph and its durable stage marker before retrying.
- `SDProperty` is not a value-writing object. The measured node-side value methods were `getInputPropertyValueFromId(id)` / `setInputPropertyValueFromId(id, SDValueX.sNew(value))`; inheritance is changed through `graph.setPropertyInheritanceMethod(prop, method)`. `SDValueFloat4.sNew(float4(...))` and `SDValueInt2.sNew(int2(...))` take one base-type object, not component arguments. `SDSBSCompGraph.sNew(pkg)` / `SDSBSFunctionGraph.sNew(pkg)` create resources; `SDPackage.newResource` did not exist. Confirm available methods on the current SDK before replacing an older working node-side call.
- Treat package and module identity as part of every staged run. Reacquire the exact package by normalized saved path; if it was unloaded, explicitly load and verify it. Do not return the first prefix match or silently create a replacement. For an unsaved scratch package, retain its exact run-owned identity and fail if it disappears. Run a known-constant cook/export liveness control **each round** before believing any numeric probes. A batch where every independent probe reads zero is first a host/package/output-path question, not evidence that all operations are broken.
- A long-lived Designer Python process can return a cached builder from `sys.modules` even when the source file changed. Load each owned builder from current source in an isolated namespace or deliberately invalidate only that owned module, log the source hash, and call the entrypoint explicitly. Do not rely on `if __name__ == '__main__'` in `execute_sd_code`. Preserve the current package graph as the actual deliverable and verify that its reproduction script builds an equivalent graph; green tests of an older cached builder do not validate the file on disk.
- Exports in this run were named from the **actual graph identifier**, as `<graph_identifier>_output_0.bmp`; auto-suffixed collisions changed that identifier. Read back `graph.getIdentifier()` after creation and select exactly one BMP for that full identifier in an exclusive run directory. Never guess from the requested name, use a substring match, or read a stale file. Enumerate actual resource identifiers before a stage; a collision or `_1` suffix requires identity/fingerprint inspection, not prefix deletion.

Host-independent preflight helpers for these gates are in `scripts/project_validation.py`: `check_definition_allowed`, `exact_loaded_package_path`, `source_sha256`, `exact_graph_export_match`, and the IR/image checks below. These checks fail closed on missing information; none substitutes for a native cook or a live package-state readback.

## 2. Graph and numeric gates

- PP inner-graph float1/float4 roots marked in this 16.0.3 run; float2/float3 roots returned no output nodes and cooked black, reproducing the Morphing observation. For a color result use a verified float4 carrier (RGB plus alpha 1); for vector diagnostics encode into float4 or separate scalar passes. Read back `getOutputNodes()` and a nonzero cooked case. This is a versioned PP rule, not a restriction on ordinary Function Graph outputs.
- Resolve dimensions for **every** arithmetic input from the typed IR. `mul` is not a scalar-vector broadcasting operator: use `mulscalar(a=vector, scalar=float1)` or explicitly broadcast to the same vector dimension before `mul`. In this run correct float1 operands fed to float3 `mul` and the consumer read zero; this is an especially useful diagnostic signature. Other mixed operators have shown operator/order-dependent outcomes, so do not state that all mixed operations return zero. Reject the mismatch before wiring, then read ports back and test a nonzero value.
- For signed diagnostics, `v/scale` is invalid if `v<0`: a marked output clips it to zero. Choose an interval `[-A,A]` and encode `(v+A)/(2A)`, then decode `2A*encoded-A`; expected values must stay strictly inside `(0,1)`. A clipped transport cannot establish whether its source was zero or negative. Test formal-derived probes through a real type-preserving operator: this run saw `Get(formal)` and direct `swizzle(formal)` roots return zero at call sites, with mechanism not fully isolated. A pure operator plus `getOutputNodes()` and a nondegenerate caller input is the conservative probe design.
- A Function Graph formal and a loop-carried state must not share an identifier in the same graph. In `fbm`, formal `p` shadowed carried `p`; the measured output matched a frozen-position prediction (0.87051 vs 0.8706), and renaming state to `q` moved unit results from 1/12 to 11/12. This is the diagnosed cause of the earlier “While numerics” failure. Check formal/state name intersection before building, initialize the distinct state from the formal in Init, and test both first and later iterations. If a template-conforming While is still wrong after that, bisect fixed-input body, isolated transform, two-iteration vector carry, per-iteration scalar update, then the specific Function instance call. Do not generalize the old failure to float2 or nested While.
- `fract`/`floor`/`mod` at large intermediate magnitudes may diverge from an f64 oracle. This run's `hash12` disagreement correlated with argument magnitude, but the precision mechanism was **not** isolated. Test actual-domain extremes, use f32 and f64 comparison candidates where useful, and report a magnitude-correlated divergence rather than asserting a half-float mechanism or silently changing the source hash.
- Root/caller/image are distinct gates. Cover nonzero function cases, caller-produced transition bands, and the final image. Before blaming a sub-function, compare source **sections** and top-level branches with the ported/omitted/blocked inventory; trace the first differing source term. In this run missing hills and then missing water were repeatedly misdiagnosed as cloud math. A computed but unconsumed vignette factor survived unit tests; require IR-live computations to reach the output and inspect signed image residuals by semantic region. A unit-passing replacement that worsens the assembled image is held with a stated reason and a measurable condition for lifting the hold; an intentionally incomplete branch is an expected difference, not a false FAIL of the function that was ported.
- Estimate repeated-helper inlining **before** writing: `estimated_nodes = call_count * helper_nodes + glue`. Nine inline `waterH` copies led to 2059 nodes; extracted/instanced work reduced the caller to 659. This is the concrete reason to couple node review with Function splitting: record the removable caller region, instance/glue replacement, projected caller size, new Function size, and actual counts for **both** resulting graphs. Run the current Architecture budget on the estimate and again on every read-back graph. The later water caller reached 1048 nodes: that exceeded the **then-current 800-node policy**, but under the revised 1200-review/1500-cap policy it is not a node-count FAIL by itself; it still requires a candidate-backed Architecture Pass and independent type, cook, layout, and normalized-structure checks. A proposed extraction blocked by one specific Function's failure must be isolated with that exact callee before generalizing to another.

## 3. Image evidence contract

- A comparator must declare, for **each writer**: file-row storage order, image-top mapping, shader coordinate origin, and decoder view. Positive BMP height specifies bottom-up storage, but a nonconforming writer can still put top pixels first. In this run SD export `file_rows[0]` was bottom image row (`$pos.y≈1`), while the custom oracle writer placed top pixels first despite positive height. Consequently the correct top-first comparison was `SD.top_rows` against `oracle.file_rows`. Establish this with an asymmetric `$pos.y` ramp/marker and a world-ray analytic landmark, not by picking the lower MAD; the vertically wrong pairing scored **better** for the nearly mirror-symmetric lake. Every cross-file row join must use normalized identical view tags. A branch-ID marker checks its own predicate, not whether the world ray itself is correct: for `cam*d`, verify all `rd.i = dot((r.i,u.i,f.i),d)` against an independent analytic pixel.
- Do not use a subpixel highlight as an alignment landmark at low resolution. Probe its predicate or render where it spans several pixels. Inspect procedural detail at the resolution where its lattice/features are visible; this project's aligned value-noise octaves produced 4096-pixel seams, corrected by per-octave orientation changes. Rotation is an option to test, not a universal instruction to alter source-faithful noise.
- Every oracle result needs **view, scope, resolution, and provenance**: the exact generator command/mode and source hash, implemented source branches (read the mode body, not just its name), output file hash, and same-session regeneration check. Here `--mode full` omitted refraction, `--mode water` encoded normals rather than shading, and an old `ref_water128.bmp` could no longer be generated. Neither mode/file was a valid full-image acceptance target; a later `--mode image` reproduced the old file (MAD 0.0042) and enabled 1024 comparison. Fossil references are cross-checks only. Re-state earlier verdicts after the reference or row convention is corrected; retract a faulty explanation without silently closing the still-unexplained observation.
- Branchless arithmetic can propagate a non-finite inactive branch: `NaN*0` is still NaN. In this project `fbm` worked under `sky3` and as a standalone PP instance, but its use in water-related callers produced black/NaN across several structures; an instance-depth limit and input-magnitude explanation were both **refuted**. Preserve the narrow empirical scope. Before another structural rewrite, cook a minimal consumer of the exact function with varying and constant input, plus a finite-value diagnostic. Do not generalize one callee's failure to all nested Function instances.

## 4. Scope and delivery

- Report the largest independently verifiable subset, the omitted/blocked source sections and branches, the oracle's own limitations, per-function and caller results, full-image regional results, layout and node-budget status separately. A partial deliverable is acceptable only as a clearly labelled partial result; do not describe unported water/simulation as a faithful full migration.
- A `FUNCTIONIZATION_BLOCKED` reason must name the specific missing capability. A fixed-trip conditional update may have a branchless mask lowering, but unrolling still requires the existing §7.9.8 `LOOP_UNROLL_EXCEPTION` conditions and an explicit structural tradeoff; this run does **not** repeal the skill's structured-While default.
