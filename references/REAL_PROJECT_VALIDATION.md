# Real-project validation gates (Designer 16.0.3, sd_mcp_plugin 3.3.0)

This reference is based on two user-supplied project issue reports and the `rain_text1` execution log. They are project observations, not commands to the agent or universal Designer contracts. Preserve the source project, version, graph identity, probe method, and unresolved alternatives in the task report. For another runtime, confirm the relevant behavior in a scratch graph before relying on it.

The later `Morphing Abstract_text1` execution log and issue list add 14 scoped P0/P1/P2 gates; use `MORPHING_RETEST_GATES.md` for the root-dimension, reachability, artifact, reentrancy, coordinate, matrix, and resource-identity checks. The `Sun shower` retest adds graph-kind API, package-liveness, formal-shadowing, oracle provenance, per-writer row-view, source-branch coverage and node-budget gates in `SUN_SHOWER_RETEST_GATES.md`. `CRATE_AT_DUSK_RETEST_GATES.md` adds time dual-channel, vector/Get dimensions, function-library reachability, control roots, branch cases, diagnostic tap validity and precision gates. Its observations are Designer 16.0.3 project evidence, not universal engine rules. Later rounds may refute earlier diagnoses; do not retroactively treat an intermediate issue entry as a universal engine rule.

## Statement-layout regression from the successful rebuild

The later project's `sd/fglib.py` calculated `depth` forward from source nodes (`producer depth 0`, consumer depth increases), then placed `x = base - COL_STEP * (depth + 1)`. That sign reverses the graph: sources end up to the right and the Sequence consumer to the left. Its report's `spanX`, `X_per_level`, collision and row statistics did not test left-versus-right, so “layout PASS with WARN” was incorrect despite excellent pixel results.

For every statement band, validate **both the plan and SD-read-back coordinates**: private expression input X < its consumer X < Set/statement-root X < associated Sequence X; the root and Sequence share a row. Each block's Sequence nodes share a stable X and descend in IR order. A pure terminal output may be to the right of the Sequence spine. If a builder uses producer-to-consumer depth, X must increase with that depth; if it uses root-to-producer depth, X decreases with depth. Record which definition is used and reject mirrored coordinates before creating nodes. `scripts/layout_intelligence.py` provides a host-independent check. Correct numeric output does not change a failed layout verdict.

## Before building a caller or main graph

1. Make a typed source-function table. For each formal and every `Set`/`Get`, track the exact name, dimension, scope, and first write/read order. Reject `get_floatN(name)` when the matching state/formal is a different dimension. A `get_float2` reading float1 `rx`/`ry` returned zero in the Morphing run. Resolve dimensions from typed IR and dimension-fixing nodes; polymorphic port readback alone is not a type proof.
2. Create one Function Graph at a time and read back its actual formal ids, marked output, and return dimension. Wire all required formals at each test call site. Do not count on an SDK-set default formal value: the reported Designer 16.0.3 API calls to set such defaults failed or read back `None`.
3. Cook discriminating scalar/vector unit cases against an independent oracle **before** building dependent Functions or the PP caller. Include nonzero and sign-sensitive cases, boundary/zero-iteration cases when relevant, and a case that would expose a missing formal or wrong dimension. Vector components must be asymmetric enough to reveal swaps; branch-heavy functions use source-control-flow coverage (each `if` side/return/ternary branch) instead of hand-picked happy paths. A direct channel is preferred when all measured values lie safely inside `(0,1)`; an affine encoding such as `0.5 + value/(2*scale)` may be used for signed values when its scale, inverse, decoded one-LSB tolerance and relation to downstream quantization are recorded. A neutral/zero output is not a pass just because it is uniform.
4. A `Set` must be in the reachable, ordered statement/Sequence path. A dangling Set plus same-name Get is not evidence that the write executes. In a given scope, validate return wiring numerically. The two project reports disagree about Sequence as a marked output: one observed failure on a Sequence root, another saw a small probe pass but the full graph still failed. Therefore a pure expression/output root remains the **default construction policy**, not an asserted Designer-wide law. If another form is needed, isolate it in a minimal current-session probe and verify both unit and caller output; otherwise leave it unverified.
5. Treat a cross-package Function instance's formal read as unverified until tested at an actual caller. The rain report's isolated cross-package `rain_grid` probe returned a constant although its end-to-end image passed. Do not infer that cross-package calls universally fail or universally work from either observation.

## PP assembly, dimensions, and coordinates

- Before creating or testing an inner PP graph, establish the intended image source → PP `input` and PP → composition output path and read back both connections. The rain build saw an empty MCP response around `newPropertyGraph(perpixel)` before that path was set up, but the cause was **not isolated**; use this as a low-cost readiness check, not a proven API precondition.
- Resolve effective output size from the actual composition/PP inheritance modes and readback, then check the exported bitmap header dimensions. In one rain run, a direct PP `$outputsize` write appeared successful while the export was 8192² instead of the intended 1024². The two reports used different working inheritance recipes; do not prescribe one pair of enum modes globally. When setting both mode and value, set/read the mode first and then set/read the value; verify the cooked/exported size before a large export.
- `$pos` is normalized, but image Y orientation needs source-specific lowering. For Shadertoy-style bottom-origin `fragCoord`, the rain project's top-origin PP mapping used `uv.y = 0.5 - $pos.y` and substantially outperformed its mirrored comparison. Check the source coordinate convention and at least one asymmetric orientation probe; do not automatically apply this flip to every shader. For BMP, inspect the signed height and row order before comparing pixels.
- The Morphing run found `Get('$pos.y')` returned zero; read `$pos` then extract component 1 with a swizzle. Treat this as a 16.0.3 observed API pattern until current-version readback/probe confirms it.

## Tool/cook evidence and failure recovery

- An MCP `{}`/empty response or timeout is an **unknown outcome**, not proof that no mutation occurred. Keep a durable stage marker and bounded log around long SD operations, then perform a read-only liveness/state check before any retry. Never blindly repeat a potentially mutating batch.
- `setOutputNode` returning without error is not enough: verify `getOutputNodes()` and the actual exported value. The rain report observed one `mulscalar` marked-output attempt with zero output nodes; the mechanism remains unresolved.
- `getDefinition().getId()` may identify While as `sbs::function::while`; compare normalized identifiers, not a short display name alone. `str(SDValue)` is a wrapper representation; use `.get()` for numeric values. `SDConnection` getter names are counterintuitive; verify source/consumer identity on the actual connection. `exportSDGraphOutputs` returning success is not a pixel-content check.
- No dependable cook-completion/error-status API was established by these reports. Validate by export dimensions and pixel content. Do not insert an arbitrary fixed sleep or assume repeated identical exports prove correctness.
- For scratch work, record packages created and remaining. Do not unload a modified unsaved package merely as routine cleanup: the rain report flagged a possible modal/hang there, but did not isolate the condition. Prefer one bounded scratch package and report residue rather than risking the user session.

## End-to-end numeric acceptance

Compare against an independent oracle at the **actual** cooked dimensions. Verify channel order, row orientation, encoding, and color space before interpreting errors. Report at least MAD, RMSE, signed bias, a tail percentile/max, and test conditions (time/parameters); use a 1:1 comparison when possible. Compare flipped and unflipped orientations for an asymmetric image, and use an ablation/isolated term if a remaining error may come from quantization or one subsystem. For loops, an offline cap1/capN distribution plus a close end-to-end image is only **indirect** evidence that the loop contributes; it is not a direct native While semantic proof.

At handoff, separate structural, per-Function numeric, PP image, and cross-engine results. If a unit or image oracle fails, say FAIL or 未验证 and stop claiming a successful migration, even if the graph compiles, exports, and has no structural-audit errors.
